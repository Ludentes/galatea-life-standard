# Review of the bridge standard 0.1, applier 0.7 and steward 0.3

This record follows the `standard-review` procedure. The commit reviewed is named with pass 1.

## Change record

Written and committed before any reader was dispatched, and before the text itself. Directions:
**stricter**, **looser**, **moved**, **new**.

The bridge standard is new. It replaces a placeholder that stood in `standard/bridge.md` so that
the applier's earlier `BR-*` citations had a public target. Its design (`docs/specs/2026-09-24-bridge-standard-design.md`) went through several spec
reviews, and a final re-check, before the maintainer approved it on 2026-09-24. Those rounds are in the
design's git history. The rulings it stands on are in the design's *Open* section:
- every new device waits for an owner;
- another admin is shown and the owner is notified;
- the binding is MQTT 5, opinionated until an industrial reason says otherwise.

### The bridge standard 0.1

Every id is new. Levels: **Serve** (devices, transports, state, commands, liveness), **Provision**
(join, commission, remove), **Box** (the broker the box runs).

| Rule | Direction | Why |
|---|---|---|
| GA-BRIDGE-1: `basis_time` is each value's observation; nothing unobservable; loss of contact is `available: false` | new | A deployed fleet's bridges restamped cached values and published `unknown` on losing a device |
| GA-BRIDGE-2: a partial read restamps only what it read | new | A read of one key made every key look fresh |
| GA-BRIDGE-3: RFC 3339 UTC with milliseconds, never ahead of the bridge's clock | new | A fast clock makes a stale value look fresh; the placeholder had the rule and the design first missed it |
| GA-BRIDGE-4: one result per accepted command within its bound; a repeated `command_id` does nothing | new | QoS 1 duplicates, and the applier's timeout rule |
| GA-BRIDGE-5: a state value is only what the device reported | new | zigbee2mqtt re-publishes commanded state by default; the applier's `acked` rests on state |
| GA-BRIDGE-6: `unreachable` within 1 s for a down transport or unavailable device; an unknown device is named in `failed(unknown_device)` | new | Silence on an unknown device cost a deployed fleet's operators a timeout per command |
| GA-BRIDGE-7: a command whose expiry has run out is never started | new | A late command runs late; a deployed dispatcher ran commands two and three times |
| GA-BRIDGE-8: `done` only on the protocol's confirmation | new | HS17, HS18: a lock's invoke status is the only word the protocol gives |
| GA-BRIDGE-9: one faulty device or transport stops no other; broker loss changes no `available` | new | HS4 |
| GA-BRIDGE-10: no exit on a recoverable fault | new | A deployed fleet's Zigbee bridge exited on every coordinator loss and restarted 916 times |
| GA-BRIDGE-11: backoff to a ceiling of at least 60 s within 180 s, reset only by a read | new | A half-open gateway held a connect-reset breaker at its floor for ever |
| GA-BRIDGE-12: persisted state that disagrees with the network serves nothing | new | A bridge store out of step with the Matter fabric or the coordinator |
| GA-BRIDGE-13: `fresh_s` for every device, `observed` only after two check-ins | new | HS17's replacement sensor; the 120 s ceiling it replaces made every sleepy sensor unobservable |
| GA-BRIDGE-14: `other_admins` as the protocol shows them | new | HS18, the phone's fabric on a lock |
| GA-BRIDGE-15: `proposed_class` states its evidence | new | HS17, a valve that reports as a switch |
| GA-BRIDGE-16: the test transport only under a harness, announced in `status` | new | So a harness refuses a bridge on a real radio, and a real home sees a test bridge |
| GA-BRIDGE-17: `ping` answered from the main loop within 1 s | new | A hung main loop with a live MQTT client never fires a will |
| GA-BRIDGE-18: connects as the binding says; subscribes before `online` | new | Commands published between `online` and the subscription were lost |
| GA-BRIDGE-19: Retain Handling 2; never acts on a retained request | new | A retained request would run again on every reconnection |
| GA-BRIDGE-20: a `0x87` refusal is a fault in `status` | new | A denied grant must not be silent |
| GA-BRIDGE-21: a removed device's retained topics are cleared | new | Ghost devices after removal |
| GA-BRIDGE-22: a graceful reload publishes `offline`, `graceful: true`, and disconnects cleanly | new | A planned restart must not read as a death |
| GA-BRIDGE-23: a transport is `up` only on an exchange within 30 s | new | A connect proves nothing (half-open gateways) |
| GA-BRIDGE-24: a generated Zigbee network key and PAN id | new | HS17, a neighbour's bulb; a default key is anyone's network |
| GA-BRIDGE-25: a join window never outlasts `window_s`; every device that joined is reported | new | HS17 |
| GA-BRIDGE-26: `near` honoured where the transport can | new | HS17, a window opened at one router, not house-wide |
| GA-BRIDGE-27: `block_rejoin` holds until `unblock` | new | HS17, the dead leak sensor must not come back |
| GA-BRIDGE-28: `join` or `commission` on the wrong kind of transport is `invalid_request` | new | Makes the two provisioning paths distinct |
| GA-BRIDGE-29: an unattested Matter device is refused unless the owner accepts it | new | matter.js accepts every attestation finding by default |
| GA-BOX-1: the broker refuses visibly; only the applier writes requests; only bridge `{b}` writes under its prefix; no rule engine writes a request | new | Mosquitto's plain ACL file filters only at delivery, so a denial is silent; a rule engine is a second writer the gate cannot see |
| GA-BOX-2: an ACL change is verified before it is relied on | new | ACL changes that did not take, in a deployed fleet |

### The applier 0.6 → 0.7

| Rule | Direction | Why |
|---|---|---|
| GA-ADOPT-1: a device new to the applier is `adopted: false`, and every action on it is refused (`not_adopted`); no safety rule reads or actuates it | new, **stricter** | The maintainer's ruling: every new device waits for an owner. HS17, HS18 |
| GA-ADOPT-2: replacement keeps the applier id, declarations and safety rules; the old identifier is retired | new | HS17, a dead leak sensor replaced without rewriting the steward's rules |
| GA-ADOPT-3: another admin on a device with actions above `reversible` is a notice, at adoption and whenever one is added | new | The maintainer's ruling: show it and notify. HS18 |
| GA-PROV-1: `provision` is the owner's, routed to the bridge that owns the transport | new | HS17, HS18: no Galatea standard could open a join window |
| GA-PROV-2: `window_closed` is a notice naming every device that joined | new | A device nobody claims is news for the household |
| GA-BUS-1 to GA-BUS-10: the applier's side of the MQTT seam (per-entry parsing, a fast clock reads `stale`, open enums, no reissue inside the bound, no retained request, `snapshot` on a gap, broker loss makes devices `dead`, a fresh ping after reconnecting, dispatch is a success PUBACK, freshness never from arrival) | new | Lessons from a deployed fleet's MQTT bridges, each listed in a research note |
| GA-STATE-2: a device is `dead` within 1 s of its bridge being found dead (10 s without a ping answer, or its will), its transport going `down`, the broker being lost, or the bridge reporting it `available: false` | **stricter** (ping in place of a status cadence; `available: false` is `dead`) | A will fires only when the connection drops; the ping catches a hung loop |
| GA-STATE-4: an open device's action ends `sent`, `failed(reason)` or `unanswered` | stricter (a result is required) | HS12, the IR air conditioner |
| GA-STATE-5: `fresh_s` is every device's effective bound; `unknown` reads `stale`; an adapter gives one for every occupancy sensor | **stricter** | HS2, HS17 |
| *Outcomes*: `unanswered` is a new final outcome; `unreachable` may follow `applied` | new | An IR step whose bridge never answers must end; a bridge may know better after dispatch |
| GA-APPLY-5: `unreachable` also covers a bridge's post-dispatch answer | **looser** (a dispatched step may end `unreachable`) | The bridge knew the device was gone; the token stays used (GA-TOKEN-4) |
| GA-APPLY-7, GA-APPLY-8: a stateless action a protocol cannot confirm ends `sent`, not `failed(no_ack)` | **looser** | Otherwise every `cover.stop` through zigbee2mqtt fails |
| GA-APPLY-8: a `done` while the device's fresh value already matches is `acked`; the first terminal outcome wins | **looser** (an `acked` with no new report) | A target that already holds produces no report (a deployed fleet's lesson) |
| GA-APPLY-9, GA-PLAN-4: `not_adopted` in the apply checks, and in the reason order after `unsupported_action` | new | GA-ADOPT-1 |
| GA-APPLY-11, GA-SAFE-8: a `late_ack` after any `failed`, and after a post-dispatch `unreachable` | **looser** (more steps can recover) | A bridge's `failed(reason)` or `unreachable` may be wrong; the device's report wins |
| GA-SAFE-3: a safety rule's final outcomes include `unanswered` | stricter (the rule completes) | A safety rule with an IR actuation must not hang |
| GA-TOKEN-4: a dispatched token stays used whatever outcome follows | stricter | A late `unreachable` must not let the token be spent twice |
| GA-META-1, GA-META-2: `sid:` built from the oldest identifier; routes and duplicates keyed on it | changed | Replacement must not change the id the steward sees |
| GA-DESC-3's table: `onoff.turn_on` on a `water_valve` or `gas_valve` is `no_voice` | **stricter** | HS17: a valve that reports as a switch; Home Assistant opens one by voice |
| Notices gain `cause` (`safety_rule`, `window_closed`, `other_admin`) | new | GA-ADOPT-3, GA-PROV-2 |
| `describe` lists `transports`, `adopted`, `other_admins`, `previous_identifiers`, `fresh_basis` | new | The owner's app needs to know where to open a window and what it is adopting |
| *What this standard governs* no longer excludes pairing; *not defined* drops "anything below an applier's bridges" | changed | The bridge standard now covers it |
| Every `BR-*` citation, `BRIDGE_STALENESS_MS` and `basisMaxAgeMs` removed | moved | To `standard/bridge.md` and the rows above |
| The harness's simulated home is simulated bridges on this binding | changed | Nothing may rest on any one system's bridges |
