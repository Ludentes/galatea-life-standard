# Review — applier 0.16

## Why

Two findings from the first light on the bench, 2026-10-11, and the plug rehearsal before it.

**The owner could not take back a tier they raised.** The owner adopted a Zigbee plug raising its
`onoff.turn_on` to `confirm`, then wanted it back at the table's tier so that a wall button's rule
could switch the lamp on it. Applier 0.15 says `configure` only raises a standard action's tier
(GA-DESC-3, *Default tiers*), and allows one lowering of a standard action, the delete of a tier a
replacement kept (GA-DESC-11). The reference applier followed the text, refusing both the lower value
and the delete, so the only way back was to remove and re-pair the plug. HS35 (scenarios 16, a wall
button for the lamp the owner once guarded) is the scenario that asks for the looser rule.

**A key's first value leased the device to a person.** Pairing a plug, and every restart of the
applier, reported each key's first value with cause `external`, which the steward takes as a
person's change and leases (GA-LEASE-2). The plug rehearsal's F3. The reference applier and the
harness already carry the fix (the harness's proposed clause `first-value-is-device`, the mutation
`externalises-a-first-value`); 0.16 writes it into the text.

**Rulings** (the maintainer, 2026-10-11), as they bear on the text:
- The raise-only rule is a defect: the owner must be able to change a tier they set; fix the
  standard, do not work around it. The *Default tiers* table, with its classes, flags, loads, hosts,
  extension floors and requested tiers, is the safety floor; "only raises" above it is policy, which
  the standards leave out (the standing ruling: no premature policy, only safety floors as MUSTs).
- A key's first value, the applier holding none before, is reported with cause `device` when the
  device is not adopted or the status is retained, and so takes no lease; a live first report on an
  adopted device stays `external`; an apply's correlation still gives an apply's cause. Narrowed from
  the build's wider proposal (below, *Open items*).

**Author's rulings** where the brief left a choice (recorded in the author's notes, here for the
readers):
- A tier below the floor is refused `invalid_request`, nothing changed, never clamped, for every
  action, as GA-DESC-14 already said for extension actions.
- The owner's value is kept as set; the tier is the higher of it and the floor, so a floor that moves
  (a load, `infrastructure`, a replacement) never rewrites what the owner chose. This changes
  GA-DESC-13, which raised the stored tier to a new floor and kept any tier at or above it: a socket
  turned from `heating` to `lighting` kept a `confirm` the table alone had given. Now it drops to its
  new default unless the owner set a tier.
- A later lowering raises no `other_admin` notice. The notice is about a guard another admin passes;
  a lowering takes the guard away for everyone and opens no door. At adoption the tier is still judged
  before a lowering in the same change set (GA-ADOPT-3), now for any action.
- A tier change in flight needs nothing new: it is a model change (GA-DESC-2), so a plan made at the
  old tier is `stale_revision` at apply (GA-APPLY-2); an inline apply, and a steward run that plans
  each step at dispatch, see the new tier; a token presented for an action now `reversible` is simply
  not needed. One sentence of explanation says so under *Default tiers*.
- `device` keeps two meanings (a `self_changing` key's change; such a first value) rather than a new
  cause: both mean that no person is taken to have acted, and a new cause is a wire change every
  client would have to learn. The text says that nothing on the wire tells the two apart.

## The maintainer's ruling on a first value (2026-10-11)

Walk F1 with Kimi H3 and H4 were held from round 1's fixes for a ruling: GA-EVT-1's "from a retained
status" could not be observed as written (a republication answering `snapshot` carries no flag; a
live report racing a retained one is not told apart) and missed restarts whose first values arrive
live, and a route move. The maintainer ruled that GA-EVT-1 defines a first value by what the applier
observes, not the retain flag, and that the rule is marked as needing real-life testing. Fixed in
52c745ca.

| Rule | Direction | Why |
|---|---|---|
| GA-EVT-1 and *Causes*: a key's first value is `device`, taking no lease unless an apply's correlation gives it that apply's cause, when it arrives while the applier loads statuses after it connects or restarts (the deliveries on subscribing), in a bridge's answer to `snapshot` or among a new instance's first statuses before that answer, over a new route after a `configure` route moves a device, or on a device not adopted; never told by the retain flag | **looser** for the lease (more first values are `device`: a bridge starting after the applier, a bridge's restart, a route move) | The maintainer's ruling (2026-10-11), on walk F1 and Kimi H3, H4 |
| *Causes*: an adapter takes the values it reads from its engine on connecting again, after the engine was unreachable or restarted, as a snapshot's; a restart it cannot see leaves those values `external` | **looser** (covers the engine's return) | The ruling asks for the adapter's engine restart to be covered where it comes as a snapshot |
| *Causes*: a report arriving live from a running bridge instance on an adopted device stays `external`, a real first press included | **unchanged** in force (restated) | The ruling |
| *Causes*: a known gap named, a plugin's server starting at adoption (GA-ADOPT-4) under its bridge's running instance, whose first values arrive live and lease the device | **new** (explanation; a known limitation) | The ruling asks for a case that does not fit to be named |
| GA-EVT-1 marked "⚠️ to be checked on a real installation", naming what to observe (a power cut with the bridge starting after the applier, a bridge's restart, an adapter's engine restarting, a route move) | **new** (a marking, not a requirement change) | The maintainer's ruling: the MUST needs real-life testing |
| Negative subjects: `externalises-a-first-value` reworded (a status delivered on subscribing, not "a retained status"); `externalises-a-snapshot-value` (GA-EVT-1, with GA-BUS-6), `externalises-a-rerouted-value` (GA-EVT-1) and `devices-a-live-press` (GA-EVT-1, the over-wide mutation) new | **new** | One for each case the ruling adds, and one for its limit |
| the workshop's backlog, *From the applier 0.16 review*: "Bench check: first-value causes across restarts" | **new** (backlog) | The ruling |
